# Contributing

The design constraint is narrow and non-negotiable: **the skill must never add
to a resume something the person has not confirmed.** A change that makes the
output more flattering by inventing experience is not an improvement.

Useful contributions:

- Section headings for languages the resume reader does not recognise yet
  (`skills/resume-gap/scripts/read-resume.py`, `HEADINGS`)
- Boilerplate phrases that should be ignored in a language you speak
- Cases where the review gave bad advice — paste the posting and what it said

Open an issue before a large change, so the work is not wasted.
